# Implementation & Tests (MTC-1.0 Phase 2)

## Patches produced

### B2 — `patch/health-tunnel-supervisor.hardened.sh`
Fixes the observed restart loop. Root cause: the running supervisor launched
`python3 health-tunnel.py` **without** exporting `HG_EDGE_URL` / `HG_EDGE_DEVICE` /
`HG_EDGE_TOKEN_FILE`, so the fail-closed tunnel exited immediately and was respawned
every 30 s (no tunnel ever stayed up; last serve `2026-10-10T00:38:59Z`).
Changes: load config from `~/.config/hg/edge.conf` + `edge_token` as **data** and export
the three vars; **fail-closed exit(2)** if config is missing (no broken respawn);
**crash-loop backoff** (1→2→…→`HG_SUP_MAXBACKOFF`, mirrors runit's immediate-exit delay);
keep exact-argv `/proc/cmdline` PID hygiene; duplicates ⇒ FAIL-CLOSED (no restart/kill).
Files: `health-tunnel-supervisor.original.sh`, `health-tunnel-supervisor.hardened.sh`
(`diff` between them is the patch).

### B5-a — `patch/hg_tool_plane.governance.patch`
Closes a real coverage gap: previously only `go_health` was canonical-mapped, so
side-effect tools (`vps_exec`, `github_api` writes) were allowed while only a local
deny-list applied. Hardened `governance_decide`:
- read-only tools may run even if canonical governance is unavailable;
- **every side-effect tool must be canonically mapped AND available AND allowing**;
  an unmapped side-effect tool is **DENIED by default** (`…UNMAPPED_FAIL_CLOSED`).
No write capability is widened. Generated by `patch/make_governance_patch.py` from the
deployed `hg_tool_plane.py` (sha256 `16AE914D516CB1496B7BA193DBC3928647788904AA2D931BFBB3564C274D3524`).
